## [1.0.0] - 2026-09-18

First release, deployed to Vercel + Neon.

### Added

- Next.js 16 + TypeScript + Tailwind v4 skeleton, Drizzle ORM against Postgres 17 (`wheel-db` container, host port 5433), same "Midnight Arcade" theme tokens/fonts as web-roll-the-dice.
- Dashboard access model: 5-character hash + optional password, iron-session-gated, join/create home page (ported from Roll the Dice's game flow, renamed).
- Presets: private/public lists (two foldouts, category+name filter, sort by category/name/created/count, per-list "Load more" pagination), create/edit (name, category, Public switch, names textarea + copy/paste/sort/deduplicate/clear tools), copy (confirmation-gated, always creates a private duplicate) and remove.
- Wheels: create/edit (name, category, template-bucket textarea + copy/paste/sort/deduplicate/load-from-preset/save-as-preset/clear tools), copy (template only, fresh current/history), remove, Reset (starts a new history session, reseeds current bucket from template).
- "Load from preset" picker (reuses the preset browser in a selection mode) with Append/Replace into a wheel's names textarea; "Save as preset" snapshots a wheel's current names into a new preset.
- The wheel screen: Sort/Shuffle the current bucket (persisted immediately), History dialog (sessions as foldouts, most recent open by default), Current-list dialog (static table ⇄ free-edit textarea), and the actual spin loop.
- Winner-first, animate-second spin engine (`crypto.getRandomValues`) with press-and-hold force: **Fair mode** (default) draws the winner independent of hold time, force only scales animation duration/cycle count; **Force-affects-odds mode** generates a fresh random permutation on press and hold duration selects a position in it (wrapping) — a real causal input to the result that isn't practically aimable.
- Four visualizations, switchable per-wheel from its Settings menu: lottery bowl (scattered names, randomly highlighted and decelerating before settling), pie wheel (rotates to land the winning arc under a fixed pointer, tangential rim-aligned labels), vertical cylinder (slot-machine reel), horizontal carousel (card reel).
- Winner banner: name (with copy-to-clipboard), datetime, Keep it / Remove it / **Remove all** (clears every occurrence of the winning name — the only way to fully clear a repeated name's weight, since weight is encoded purely via duplicate entries, not an explicit field).
- Sound: click taps, one fixed tick sound per visualization (ticked repeatedly through a spin with small pitch jitter), a winner-reveal chime — real clips with a synthesized fallback per category, Sound on/off toggle (persisted) in both Settings menus.
- Categories: ten shared categories (Movies/Books/Music/Series/Games/Board games/IT/Landmarks/Locations/General) as code constants, not DB-backed.

### Fixed

- `WheelEditDialog`'s Reset button discarded the updated wheel data instead of returning it to the caller, which would have left an open wheel screen showing a stale current/history bucket after a reset.
- Copy and Paste tool buttons gave no visual feedback either way, so a successful Copy looked identical to a failed one; both now flash green/red, and Paste's failure state explains that Ctrl+V works as a reliable fallback when the browser blocks clipboard-read (very common).
- The winner banner's gradient name text was invisible — Tailwind's `bg-clip-text` utility wasn't being generated by this project's build; replaced with an equivalent inline style.
- Preset Copy fired immediately with no confirmation, despite the spec asking for the same confirm-gating as Remove.
- Names typed/pasted into any textarea were silently re-sorted alphabetically on every save; now they keep whatever order they were entered in, and Sort is an explicit tool button only.
- The lottery bowl's scatter area let names land close enough to the container edges to render partly outside the viewport at larger (highlighted/settled) scale; tightened the placement range and capped each name's width with truncation as a safety net.

### Security

- Every wheel/preset Server Action (sort/shuffle/edit/copy/reset/remove/record-winner/list) took a bare numeric id with no check that the caller's session had unlocked the owning dashboard — since ids are sequential and Server Actions are directly callable, this let anyone bypass a dashboard's password entirely and read or modify any dashboard's data. Added session-based ownership checks (`src/lib/authz.ts`) to every one of these actions, plus closed a related gap where renaming a password-protected dashboard didn't require its password.
